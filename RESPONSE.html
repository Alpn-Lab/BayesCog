    Response to reviewers - round 1

    We would like to thank both reviewers for ther time with reviewing both the manuscript and the accompanying BayesCog course repository. Below we respond to each comment in turn, highlighting the specific changes made to the paper and course materials.

    @DrCatHicks

    1. “Community guidelines: while there are clear notes for contributing, I noticed the support guidelines are a bit thin if someone runs into trouble installing. This is a minor note as dependencies and installation are well-described in the paper, but quickly adding a Getting Help or further troubleshooting section to README could help a reader onboard.”

    Thank you for this suggestion. We have now added a dedicated Getting help section to the repository README. It points readers first to the setup/installation instructions — including the pre-built Docker image as a fallback for anyone who has trouble with the local renv installation — and then explains how to ask a question about the course content or report a problem by opening an issue on the GitHub repository, with a contact route for anything not covered there. The section also links to the contribution guidelines for readers who would like to fix or improve something themselves.

    Files changed: README.md

    2. “It may be nice to consider a separate contributors.md file so that contribution guidelines do not only live in the README (this is also slightly confusing when paper states to look for contributors page).”

    We agree, and have made both changes. The contribution guidelines now live in a separate CONTRIBUTING.md file at the root of the repository . We have also corrected the manuscript, which now notes that accepted contributions “will be credited and acknowledged in the Contributors section of the repository README”.

    Files changed: CONTRIBUTING.md, paper.md

    3. “License should be updated to OSI approved. Creative Commons License only, but OSI license is required for code components. Suggested minor revision to add OSI approved license. License is otherwise clear and correctly in a LICENSE file.”

    We have relicensed the entire repository under the OSI-approved MIT license (LICENSE), replacing the previous Creative Commons Attribution-ShareAlike 4.0 license. The README License section has been updated accordingly.

    Files changed: LICENSE, README.md

    4. “Workshops 10 and 11 are marked ‘WIP’ and noted as ‘yet to be added.’ I am curious to know JOSE’s stance on this… if these are living breathing course materials, does JOSE want the paper to remain consistent with the listed workshops?”

    Thank you for clarifying the journal’s position on this. We have decided to simply remove these workshops from the course, retaining only those which are completed.

    Files changed: course_overview.qmd, README.md

    5. “The paper has a Future Directions section but no statement about how long the course takes, what size of class it works for, or what level of instructor expertise is needed… no particular guidance for instructors on how to adopt the materials (e.g., what a semester looks like, what prerequisites to set), and no discussion of student numbers or outcomes, although the README hints at impact.”

    We have now added explicit usage and instructor guidance to the manuscript. The new text states that the course is designed to be delivered over a semester, with each workshop taking approximately two to three hours; that it suits classes of any size but is best suited to smaller cohorts of roughly 10–20 students given the hands-on, debugging-heavy nature of the material. We note that the instructor is expected to be proficient in R and Stan and comfortable with Bayesian statistics, whilst a familiarity in experimental psychology/neuroscience may be useful but is not explicitly required. We also added a week-by-week course structure as two tables — Table 1 (conceptual foundations, Weeks 1–3) and Table 2 (practical modeling, Weeks 4–9).

    Files changed: paper.md

    6. “R Basics workshop goes through quite a few core programming concepts quickly, and I can imagine many learners struggling here… a possible place to expand to the adaptation of this workshop to a programming-naive audience or signal to teachers that they may need to adapt this portion… Refinement to the learning objectives might also help, e.g., ‘this assumes prior x knowledge’ about statistics or programming.”

    We have addressed this on both the website and in the paper. The R Basics workshop page now opens by stating that it assumes no prior programming experience, and acknowledges R cannot be fully covered in a single session, providing users to external resources for continued study. The manuscript’s usage paragraph now explicitly signals to instructors that, because the first workshop introduces core programming concepts at a brisk pace, they may wish to adapt this portion for a programming-naive audience — for example by allocating additional time, adding supplementary materals, or directing students to supplementary resources.

    Files changed: workshops/01.R_basics/qmd/intro.qmd, paper.md

    7. “The paper does not really tell the ‘story’ of workshop development or author expertise; a short paragraph on this could be added… functional/methodological expertise might be useful in keeping with JOSE checklist.”

    We have added a short development-history paragraph to the manuscript, noting that both authors are active researchers in computational modeling and cognitive neuroscience who apply these Bayesian methods in their own work, providing relevant citations.

    Files changed: paper.md

    8. “DOIs appear missing in references.”

    We have carried out a full reference pass and added DOIs to every entry for which a DOI exists.

    Files changed: paper.bib

    9. “Learning objectives… could be elaborated a little bit on each workshop page (e.g., workshop 4 says ‘By the end of this tutorial, you’ll have the foundational skills needed to implement more complex Bayesian models…’ which is not super specific). I would encourage less high level descriptive and more functional learning objectives, e.g., ‘by the end of this workshop you will be able to perform x task in y context’ to make objectives more assessable and grounded for learners.”

    We have revised the learning objectives for all workshops. Each workshop page now opens with a standardized “By the end of this workshop, you will be able to:” block of objectives.

    Files changed: the introduction page of all nine workshops (workshops/*/qmd/intro.qmd)

    10. “Paper has a minor typo… ‘following the community guidelines outlined on the CONTIBUTORS page’.”

    Thank you for highlighting, this has been corrected.

    Files changed: paper.md

    @aloctavodia

    1. “The figure for joint probability is before the section on joint probability, and the figure for conditional probability is before the section on conditional probability. The same for marginal probability. Additionally, the figure for marginal probability is missing, and instead, the figure for conditional probability is repeated.”

    Thank you for highlighting this issue. We have moved each figure so that it now follows the section heading and description it illustrates, rather than preceding it. We have also replaced the duplicated conditional-probability figure with the correct marginal-distribution figure.

    Files changed: workshops/01.R_basics/qmd/probability.qmd

    2. “While this is true for direct implementation of MCMC, modern MCMC samplers actually sample in the unconstrained space… they transform bounded parameters to unbounded space and sample there. Usually, the main issues with NUTS are related to the geometry or curvature of the sampling space, like funnels or sharp ridges.”

    Thank you for noting this technical definition. We have revised the text accordingly, by framing the analogy as describing a direct implementation of MCMC, adding that modern samplers such as Stan’s NUTS instead transform bounded parameters onto an unconstrained space, sample there, and transform back — so that the practical difficulties usually arise from the geometry of the posterior rather than from the boundaries.

    Files changed: workshops/06.reinforcement_learning/qmd/hierarchical_modeling.qmd

    3. “…it is not clear to me if the boundaries are ‘real’… or just ‘practical’ boundaries. Also, why use a Normal truncated to [0, 1] instead of a Beta distribution? For the other parameter, a scaled Beta may be used.”

    We have expanded this part of the hierarchical-modeling page. We now discuss the choice of prior for the bounded learning-rate parameter explicitly, and have added a figure comparing these two candidate priors on the interval [0, 1] — a truncated Normal and a Beta(2, 5). The accompanying text notes that a Beta distribution is indeed a natural alternative for a parameter bounded on [0, 1]. We stick with our original Normal prior, but explicitly mention that the priors used in the tutorial are pedagogical choices and should be adapted to the reader’s own research context, theory, and literature.

    Files changed: workshops/06.reinforcement_learning/qmd/hierarchical_modeling.qmd, images/06.reinforcement_learning/hrch/prior_normal_vs_beta.png

    4. “The ‘highest mountain’ analogy could be confusing because with MCMC we are not trying to find the peak of the posterior distribution, we are trying to sample from the entire posterior… This could be changed to something like ‘explore the landscape’, ‘map the valleys and peaks of the mountain range’.”

    Thank you for clarifying this description. We have now reworded it to describe MCMC as trying to “map out an entire mountain range — its valleys, ridges and peaks”, and now state explicitly that the goal is not to find the single highest peak but to chart the whole landscape, spending proportionally more time in the higher / more probable regions.

    Files changed: workshops/02.binomial_globe/qmd/mcmc.qmd

    5. “‘Effective Sample Size (n_eff): This tells us how many truly independent samples we got…’ This can be confusing because we never get any truly independent samples… better to say: The effective sample size is an estimate of the number of independent samples with the same amount of information as the correlated samples we got from our model.”

    We have adopted your suggested framing. The effective sample size is now defined as “an estimate of the number of independent samples that would carry the same amount of information as the (autocorrelated) samples we actually got from our model.”

    Files changed: workshops/02.binomial_globe/qmd/stan_binomial.qmd

    6. “Gelman and collaborators recommend using ‘R-hat’ instead of ‘Gelman-Rubin statistic’. Also, the (Gelman & Rubin, 1992) citation is outdated… the current reference for ‘modern’ R-hat is Vehtari et al. (2021), ‘Rank-Normalization, Folding, and Localization: An Improved R-hat…’, Bayesian Analysis 16(2).”

    The statistic is now referred to as “R-hat (R̂)” throughout the relevant page, and we have added the modern Vehtari et al. (2021) reference as the citation.

    Files changed: workshops/02.binomial_globe/qmd/stan_binomial.qmd, paper.bib

    7. “While trace plots are still commonly used, rank plots can be more informative. For instance mcmc_rank_ecdf(x, prob = 0.99, plot_diff = TRUE) from the bayesplot package.”

    Thank you for this recommendation. We have added a follow-up section introducing rank plots as a more sensitive alternative to trace plots, and plot these on the page directly below the trace plots.

    Files changed: workshops/02.binomial_globe/qmd/stan_binomial.qmd, workshops/02.binomial_globe/_scripts/binomial_globe_main.R, workshops/02.binomial_globe/_scripts/binomial_globe_main_master.R

    8. “I recommend that you switch from WAIC to PSIS-LOO-CV… provides a more robust estimate in practice, includes a diagnostic for when the approximation is failing, and packages like loo allow improving the approximation using moment matching… in ArviZ 1.0 we removed WAIC and only report PSIS-LOO-CV.”

    We agree and have switched the model-comparison workshop over to PSIS-LOO-CV. We removed WAIC as the criterion taught and now centre the workshop on PSIS-LOO-CV, demonstrating it’s preference over alternative criteria (AIC, DIC and BIC) for Bayesian modeling.

    Files changed: workshops/08.compare_models/qmd/intro.qmd, workshops/08.compare_models/qmd/model_comparison.qmd, workshops/08.compare_models/_scripts/compare_models_main_master.R

    9. “I try to avoid that term [‘belief’] and instead use ‘guess’/‘informed guess’, ‘information’, ‘domain knowledge’, ‘prior knowledge’, ‘background knowledge’, ‘assumptions’, etc. … potentially less confusing for people new to the field, and avoids the philosophical baggage.”

    We have reworded the inappropriate uses of “belief” across the workshop pages, using instead the term “knowledge” or “assumption” when concerning prior/posterior parameters.
